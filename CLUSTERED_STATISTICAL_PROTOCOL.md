# TrajPilot CityFlow — Clustered Statistical Protocol

## Why this correction was necessary

Trajectory windows are created with overlapping temporal histories/futures from the same vehicle track. These windows are not independent observations. The prior ablation script described its bootstrap as "trajectory-level" but sampled individual windows uniformly with replacement. It also ran paired Wilcoxon and paired t-tests on window-level errors. This understates uncertainty when errors within the same vehicle track are correlated.

## Corrected procedure

The corrected `scripts/run_highway_ablation.py` uses:

1. **Confidence intervals:** resample unique `traj_id` groups with replacement. Every selected group contributes all of its test windows. ADE/FDE point estimates remain window-weighted to preserve the benchmark's estimand; each bootstrap replicate is a pooled mean over the selected track groups.
2. **Paired tests:** first compute one mean ADE/FDE per trajectory group for each model, then run paired Wilcoxon signed-rank and paired t-tests on the paired track-level summaries.
3. **Multiple comparisons:** Holm-Bonferroni adjustment is applied across the six FDE comparisons (three model pairs × two highway datasets). Significance is based on adjusted p < 0.05.
4. **Explicit reporting:** result tables record test-window count, number of trajectory clusters, bootstrap unit, and whether session-level inference has been established.

The statistical helper functions are in `scripts/cluster_statistics.py`.

## Critical limitation: trajectory cluster is not recording/session cluster

The current split is vehicle/trajectory-disjoint, not recording/session-disjoint. Multiple vehicle tracks can come from the same TGSIM run. Tracks within a run may share camera conditions, traffic state, geometry, weather, and other sources of dependence.

Therefore, these corrected intervals and p-values are **trajectory-cluster** inference only. They do not establish generalization to independent collection sessions. A final paper making session-level claims needs:
- a recording/run identifier preserved for every window;
- a recording/session-disjoint test design, or a defensible hierarchical resampling scheme that samples runs and then tracks within runs;
- enough independent runs for stable uncertainty estimates.

The corrected pipeline writes `Session_Level_Inference = NOT_ESTABLISHED` rather than claiming session independence.

## Consequence for historical tables

Any confidence interval or significance claim previously generated by the window-level bootstrap / window-level paired tests must be treated as provisional and regenerated. Updating the code does not update the old result files in `data/results` or the manually written values in the research report.

## Reproduction

After restoring the exact TGSIM files and running the corrected ablation pipeline:

```bash
python scripts/run_highway_ablation.py
```

The resulting `bootstrap_confidence_intervals.csv` and `paired_model_tests.csv` must be archived with the input data hashes, code commit, split manifest, and checkpoint/scaler hashes. Do not copy their values into the final manuscript until the output and run provenance have been audited.
